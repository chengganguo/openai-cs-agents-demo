# 企业 AI Agent 第三阶段开发需求文档

> 文档主题：客户前台与企业管理后台分离  
> 文档版本：V0.1（评审稿）  
> 文档日期：2026-07-13  
> 当前状态：阶段 3A 已实现，阶段 3B/3C 待开发  
> 适用项目：Enterprise AI Support Agent

## 1. 文档目的

本文档基于当前项目界面、第二阶段实现状态和《界面展示问题》中的产品定位讨论，定义下一阶段的产品信息架构、用户角色、功能范围、权限边界和验收标准。

本阶段的核心目标是将当前用于演示的“客户对话 + Agent 编排工作台 + 知识管理”统一界面，升级为面向两类不同用户的正式产品：

1. **客户服务前台**：由购买本平台的 AI 企业提供给其下游客户使用。
2. **企业管理后台**：由 AI 企业的管理员、知识人员、客服和运营人员使用。

两个产品界面共用 Agent 编排、知识检索、会话、审批和审计服务，但必须具有独立入口、独立导航、角色权限和信息展示边界。

## 2. 与现有需求的关系

### 2.1 上游文档

- `phase-2-enterprise-pilot-requirements.md`：定义租户隔离、企业知识库、知识缺口、审批、持久化和试点安全要求。
- `phase-2-implementation-status.md`：记录第二阶段本地试点能力及尚未完成的生产化事项。

### 2.2 本文档的调整范围

本文档不推翻第二阶段的数据、知识和审批能力，只调整产品界面和使用边界。

本文档替代第二阶段 `FR-10 管理端与工作台信息架构` 中将“客户对话”与管理模块放在同一个一级导航下的方案。后续应将客户对话从管理后台中拆出，形成独立客户前台。

## 3. 当前问题

### 3.1 当前界面混合了两类用户

当前页面同时展示客户聊天窗口和 Agent 内部工作台。该方式便于产品演示和开发调试，但不适合正式交付：

- 下游客户可能看到 Agent 路由、工具调用、护栏结果和内部上下文。
- 企业运营人员缺少面向管理任务设计的完整后台导航。
- 无法按企业品牌独立发布客户服务入口。
- 客户身份、企业管理员身份和平台管理员身份容易被混淆。
- 移动端只是切换“客户对话/编排工作台”，没有形成真正的产品边界。

### 3.2 管理后台模块不完整

当前已实现以下四个核心模块：

1. Agent 工作台。
2. 知识中心。
3. 知识缺口。
4. 审批中心。

这些模块属于企业管理后台，但要形成可交付产品，还需要补充成员与角色、企业设置、渠道发布、连接器、审计日志、质量评测和运营分析等管理能力。

## 4. 产品定位

### 4.1 商业关系

本产品采用 B2B2C 服务关系：

| 参与方 | 身份 | 使用产品 |
| --- | --- | --- |
| 平台运营方 | 本产品的建设和运营企业 | 平台运营管理能力 |
| AI 企业客户 | 购买并配置 Agent 的企业 | 企业管理后台 |
| AI 企业员工 | 管理员、知识人员、客服、运营人员 | 企业管理后台 |
| 下游客户 | 向 AI 企业咨询产品、技术、售后或账单问题的用户 | 客户服务前台 |

### 4.2 知识库责任

企业产品知识库应主要由使用本平台的 AI 企业建立和维护：

- AI 企业负责其产品说明、售后政策、价格、SLA、合同条款、安全合规资料的真实性和时效性。
- 平台负责提供导入、解析、审核、版本、权限、检索、引用、知识缺口和审计工具。
- 平台可以维护公共操作指南和通用技术知识，但必须与企业私有知识明确区分。
- 未经企业审核的聊天内容和互联网资料不得自动进入正式知识库。
- 外部网页搜索默认关闭；后续启用时，只允许企业配置的官方域名，并标记为外部未审核来源。

## 5. 产品目标

### 5.1 本阶段目标

1. 客户前台与企业管理后台具有独立入口和导航。
2. 下游客户只能看到完成服务所需的信息，不能看到 Agent 内部执行细节。
3. AI 企业能够配置自己的品牌、客户入口和知识内容。
4. 管理后台按角色展示 Agent、知识、缺口、审批和设置能力。
5. 客户身份、企业员工身份和平台运营身份具有明确权限边界。
6. 未收录资料继续执行“资料不足 + 知识缺口 + 人工升级”闭环。

### 5.2 成功定义

AI 企业管理员可以完成“配置企业品牌、发布客户入口、维护产品知识、分配后台角色、查看服务质量”的完整流程；下游客户可以通过独立前台获得有来源的回答，并且无法访问任何后台入口或内部执行数据。

## 6. 非目标

以下内容不纳入本阶段：

- 不建设完整 CRM、工单、财务或客服坐席系统，只保留连接器能力。
- 不建设原生移动 App，继续使用响应式 Web 或嵌入式组件。
- 不开放任意互联网自动搜索。
- 不允许 Agent 自动发布正式知识。
- 不建设公开应用市场和复杂多模型编排市场。
- 不在本阶段实现完整商业计费、套餐购买和发票系统。
- 不向下游客户开放 Agent Prompt、模型参数、工具参数或护栏详情。

## 7. 用户角色与权限

### 7.1 角色定义

| 角色 | 主要职责 |
| --- | --- |
| `end_user` | 使用客户前台咨询、查看自己的会话和引用、提交反馈或申请人工服务 |
| `support_agent` | 查看授权会话、处理人工升级、查看执行轨迹和知识缺口 |
| `knowledge_editor` | 上传、编辑、分类和提交企业知识 |
| `knowledge_reviewer` | 审核、发布、驳回、下线和回滚企业知识 |
| `tenant_admin` | 管理成员、角色、品牌、渠道、连接器、数据策略和企业级设置 |
| `platform_operator` | 管理租户状态和平台运行，不默认读取企业私有知识正文或客户会话 |

### 7.2 模块权限矩阵

| 模块 | 终端用户 | 客服人员 | 知识编辑 | 知识审核 | 企业管理员 | 平台运营 |
| --- | --- | --- | --- | --- | --- | --- |
| 客户服务前台 | 使用 | 可模拟/协助 | 可模拟 | 可模拟 | 可预览 | 不默认使用 |
| Agent 工作台 | 无权限 | 有权限 | 只读可选 | 只读可选 | 有权限 | 仅运维授权 |
| 知识中心 | 无权限 | 只读可选 | 编辑 | 审核发布 | 完整权限 | 无私有正文权限 |
| 知识缺口 | 无权限 | 处理/分派 | 补充内容 | 验证关闭 | 完整权限 | 仅汇总指标 |
| 审批中心 | 仅处理属于自己的确认 | 按业务授权 | 无默认权限 | 无默认权限 | 完整权限 | 无默认权限 |
| 成员与角色 | 无权限 | 无权限 | 无权限 | 无权限 | 完整权限 | 租户开通权限 |
| 审计与设置 | 无权限 | 受限只读 | 无权限 | 发布相关只读 | 完整权限 | 平台级数据 |

前端隐藏入口不能替代后端授权。所有资源访问必须由后端验证租户、用户、角色和资源所有权。

## 8. 目标信息架构

### 8.1 客户服务前台

建议本地和试点路由：`/support`。

生产环境支持企业自定义子域名或嵌入式组件，例如：

```text
support.customer-ai.com
```

客户前台仅包含：

1. 企业品牌与服务状态。
2. 智能对话。
3. 当前用户的历史会话。
4. 回答引用和来源查看。
5. 满意度反馈。
6. 人工升级入口和处理状态。
7. 隐私政策、数据使用说明和必要的服务声明。

客户前台不得包含：

- Agent 列表、handoff 和路由过程。
- 工具名称、调用参数和原始返回值。
- 护栏名称、判断理由和安全规则。
- 内部账户 ID、租户 ID、审计 ID 和内部备注。
- 知识编辑、知识缺口管理和审批管理入口。
- 模型供应商、Prompt、Token 或成本信息。

### 8.2 企业管理后台

建议本地和试点路由：`/admin`。

建议一级导航：

```text
企业管理后台
├── 概览
├── Agent 工作台
├── 会话与人工服务
├── 知识中心
├── 知识缺口
├── 审批中心
├── 质量与分析
├── 成员与角色
├── 审计日志
└── 系统设置
    ├── 企业品牌
    ├── 客户服务渠道
    ├── 业务连接器
    ├── 模型与额度
    └── 数据与安全
```

### 8.3 平台运营后台

平台运营能力不与企业管理后台混用。若本阶段暂不建设独立平台后台，至少应保留独立角色和接口命名空间，并禁止平台运营人员默认读取企业私有正文和完整会话。

## 9. 功能需求

## 9.1 FR-01 前后台入口与路由分离（P0）

### 需求

1. 将客户前台和管理后台拆分为独立路由树，最低要求为 `/support` 与 `/admin`。
2. 两个界面使用独立布局、导航、页面标题和权限检查。
3. 客户前台不得加载或渲染管理后台组件和管理数据。
4. 管理后台可以提供“预览客户前台”，但预览必须明确标记为预览模式。
5. 未登录访问管理后台时进入企业登录流程；无后台角色时返回 `403` 页面。
6. 客户入口根据绑定域名或签名配置识别租户，不接受用户手工提交 `tenant_id` 作为授权依据。
7. 当前根路由 `/` 应根据部署配置跳转到客户前台或管理后台，不再展示混合工作台。

### 验收标准

- 下游客户从客户入口无法看到、访问或通过接口获取后台模块。
- 管理后台切换模块不会复用客户前台的公开导航。
- `/support` 和 `/admin` 在桌面端和移动端均可独立使用。
- 浏览器直接修改路径访问无权限页面时，后端和前端均拒绝访问。

## 9.2 FR-02 企业品牌与渠道配置（P0）

### 需求

1. 企业管理员可配置企业名称、Agent 名称、Logo、主色、欢迎语和客服声明。
2. 支持配置客户前台的建议问题，不得将其写死为平台统一内容。
3. 支持配置人工服务名称、可服务时间和升级提示。
4. 支持客户域名或嵌入渠道配置，并显示验证状态。
5. 所有品牌配置必须按租户隔离并具有默认回退值。
6. 前台不得显示平台开发名称 `Enterprise Agent`，除非租户主动保留平台品牌。

### 验收标准

- 企业管理员修改品牌并发布后，新打开的客户前台展示该企业配置。
- A 企业的品牌、欢迎语和建议问题不会出现在 B 企业前台。
- 配置缺失时使用安全、明确的默认值，不显示空白标题或失效图片。

## 9.3 FR-03 客户对话与会话历史（P0）

### 需求

1. 客户前台支持新建会话、发送消息、流式响应、继续历史会话和归档会话。
2. 已登录用户只能查看自己的会话；客服查看会话需要后台权限和业务授权。
3. 前台展示 Agent 的业务身份，例如“技术支持助手”，不展示内部 Agent 类名。
4. 错误状态至少区分：资料不足、需要澄清、模型服务不可用、业务系统不可用和权限不足。
5. 对话中不得泄露系统 Prompt、内部上下文、工具原始输出或其他客户信息。
6. 可选匿名访问必须由企业管理员显式开启；匿名用户不得调用账户、账单和其他身份敏感工具。
7. 对话保留期限和用户删除能力遵循企业数据策略。

### 验收标准

- 服务重启后，已登录用户可以继续自己的历史会话。
- 用户不能通过会话 ID 访问其他用户或其他租户会话。
- 模型或连接器故障不会被显示为“知识库没有资料”。
- 匿名会话不能获得任何账户级敏感数据。

## 9.4 FR-04 引用、资料不足与用户反馈（P0）

### 需求

1. 有依据回答应展示文档标题、版本、章节或页码和可访问引用。
2. 引用访问必须再次进行租户、用户和文档权限校验。
3. 没有足够资料时明确说明“企业知识库暂未收录可靠资料”，不得使用无关平台知识兜底。
4. 资料不足时允许用户补充问题、申请人工服务或提交该问题供企业完善知识。
5. 每个回答支持“有帮助/无帮助”反馈；无帮助反馈允许选择原因。
6. 反馈、知识缺口和人工升级可以关联到原会话和回答，但不能未经审核自动发布为知识。

### 验收标准

- 未收录 DeepSeek 售后政策时，不返回通用 API 故障文档作为答案。
- 发布该企业的 DeepSeek 售后政策后，相同问题能够返回正确资料和引用。
- 无权限文档不会通过引用标题、摘要或链接泄露。

## 9.5 FR-05 人工升级与服务状态（P1）

### 需求

1. 用户可以在对话中申请人工服务，并看到已提交、处理中、已解决或已关闭状态。
2. 系统记录升级原因、会话摘要、优先级、目标团队和关联会话。
3. `SEV-1`、安全事件、法律承诺和重大商业承诺根据企业规则自动建议升级，但不能绕过服务端权限。
4. 未接入真实客服系统时，应明确标记为本地试点队列，不能伪造已经联系人工团队。
5. 接入真实系统后，通过连接器同步外部工单 ID 和状态。

### 验收标准

- 人工升级记录可在后台查询，并可追溯到原会话。
- 重复点击不会创建重复升级记录。
- 外部连接器失败时保留本地失败状态和重试信息。

## 9.6 FR-06 管理后台导航与角色控制（P0）

### 需求

1. 管理后台根据用户角色生成可见导航，不显示无权限模块。
2. 无权限用户即使直接访问 URL 或调用 API，也必须被拒绝。
3. 顶部区域展示当前企业、当前用户和必要的环境标识，不直接展示内部租户 ID。
4. 支持退出登录；多企业用户后续可支持企业切换，本阶段至少保证单会话只有一个可信租户上下文。
5. 移动端使用适合管理后台的折叠导航，不再以“客户对话/编排工作台”作为二选一切换。

### 验收标准

- 各角色只看到权限矩阵允许的模块。
- 修改浏览器本地状态不能提升后台权限。
- 页面刷新后保持合法当前模块，并重新验证身份。

## 9.7 FR-07 Agent 工作台（P0）

### 需求

1. Agent 工作台定位为企业内部运营、调试和服务排障工具。
2. 展示授权会话的 Agent 路由、handoff、执行时间、工具调用、护栏结果和人工接管状态。
3. 敏感字段必须脱敏；API Key、访问令牌、完整支付信息不得展示。
4. 支持按会话、时间、用户、Agent、状态和请求关联 ID 查询。
5. 客服只能查看其业务范围内的会话；企业管理员权限不应自动突破文档级内容权限。
6. 工作台中的客户对话仅作为所选会话的检查视图，不作为面向客户发布的聊天入口。

### 验收标准

- 客户前台不包含工作台代码路径或内部数据接口响应。
- 运营人员可以从失败会话定位到 Agent、工具、护栏或基础设施错误。
- 日志展示遵循脱敏和数据保留策略。

## 9.8 FR-08 知识中心（P0）

### 需求

1. 沿用第二阶段已实现的文档新建、上传、发布、下线和检索测试能力。
2. 在后台明确展示“企业私有知识”和“平台公共知识”的来源层级。
3. 企业私有知识由企业编辑和审核人员维护，平台运营人员不默认拥有正文读取权限。
4. 补充知识空间、版本、生效/失效时间和文档访问角色的管理入口。
5. 提供发布前检索测试和客户前台回答预览。
6. 上传内容中的指令只作为不可信资料处理，不能改变 Agent 策略或触发工具。

### 验收标准

- 企业用户可以在不修改代码的情况下完成知识上传、审核、发布、验证和下线。
- 未发布、已失效、已下线或无权限资料不能进入客户回答。
- 历史回答仍可审计到当时使用的知识版本。

## 9.9 FR-09 知识缺口（P0）

### 需求

1. 沿用第二阶段知识缺口队列，并增加来源渠道、问题频次、影响用户数和反馈关联。
2. 支持筛选、合并重复问题、分派负责人、关联知识和回归验证。
3. 状态至少包含 `new`、`triaged`、`content_needed`、`published`、`resolved`、`rejected`。
4. 知识发布后可重新执行原问题验证，但关闭缺口必须由授权人员确认或满足明确规则。
5. 基础设施故障、权限拒绝和真正的知识未命中必须分别统计。

### 验收标准

- 管理员可以完成“发现缺口、补充资料、审核发布、重新验证、关闭”的完整闭环。
- 智谱服务故障、解析失败或连接器超时不会被错误计入知识缺口。

## 9.10 FR-10 审批中心（P0）

### 需求

1. 沿用第二阶段服务端审批状态机，不接受模型传入的确认布尔值作为执行依据。
2. 按角色展示待审批、已批准、已拒绝、执行失败、已过期和已取消事项。
3. 审批详情展示动作摘要、发起人、目标系统、参数摘要、风险等级和审计记录。
4. 高风险动作支持企业配置的审批角色或双人审批规则，复杂审批编排可作为后续能力。
5. 重复审批和重复执行必须幂等。

### 验收标准

- 无有效审批记录时，工单、商机、账单案例等写操作不能执行。
- 审批人无法审批超出其租户和角色权限的操作。
- 执行失败时可以查看原因并按幂等规则重试。

## 9.11 FR-11 成员与角色（P1）

### 需求

1. 企业管理员可查看成员、邀请成员、停用成员和分配角色。
2. 正式环境与企业 OIDC/SSO 用户映射，浏览器不得保存管理凭据。
3. 支持角色变更审计和高权限角色变更二次确认。
4. 停用用户后，其管理会话和访问令牌应按策略失效。
5. 自定义角色和资源级授权可后续扩展，本阶段先使用预定义角色。

### 验收标准

- 角色变更后，导航和后端权限在新的有效会话中一致生效。
- 被停用成员不能继续调用管理接口。
- 所有成员和角色变化均可审计。

## 9.12 FR-12 系统设置、连接器与模型配置（P1）

### 需求

1. 企业设置至少包含品牌、客户渠道、业务连接器、模型与额度、数据与安全五个分区。
2. 连接器密钥和模型 API Key 进入服务端密钥管理，不返回给浏览器或模型上下文。
3. 当前默认使用平台配置的智谱模型；租户 BYOK 作为可配置能力评估，不要求在本阶段强制交付。
4. 支持配置会话和日志保留期、官方域名白名单及允许的客户访问模式。
5. 设置变更必须经过权限校验、必要确认和审计。

### 验收标准

- 未授权用户不能查看或修改企业设置。
- 浏览器接口、日志和 Agent 轨迹中不出现完整 API Key。
- 设置变更只影响当前租户。

## 9.13 FR-13 质量、分析与审计（P1）

### 需求

1. 提供会话量、知识命中率、知识缺口率、人工升级率、反馈满意度、工具成功率和服务错误率。
2. 区分知识未命中、权限拒绝、模型故障、检索故障和连接器故障。
3. 支持按时间、Agent、渠道和知识空间筛选。
4. 审计日志记录登录、权限变更、知识发布、审批、写操作、连接器配置和数据删除。
5. 平台运营只查看必要的租户级聚合指标，不默认读取企业私有正文和完整会话。

### 验收标准

- 每个核心指标有明确计算口径和数据来源。
- 管理员可以从异常指标定位到有权限查看的会话或审计记录。
- 指标不混淆基础设施失败和业务上的知识缺口。

## 11. 非功能需求

### 11.1 安全与隔离

- 管理后台正式环境必须使用 OIDC/SSO，不能使用浏览器可见的开发令牌。
- 客户前台和管理后台使用独立的会话 Cookie 或令牌受众，避免权限混用。
- 所有数据库记录、缓存键、对象存储路径和日志均包含可信租户边界。
- 客户前台使用内容安全策略、速率限制、防滥用和必要的 CSRF 防护。
- 管理操作、知识发布、审批和设置变更必须写入审计日志。

### 11.2 性能

- 客户前台首屏 `p75 <= 2.5s`，不包含首次模型响应时间。
- 常规管理列表接口 `p95 <= 500ms`。
- 流式对话首字延迟沿用第二阶段目标 `p95 <= 8s`。
- 后台统计和查询不得阻塞实时客户对话链路。

### 11.3 可用性与错误处理

- 客户前台必须为模型、知识检索、业务连接器和网络错误提供不同状态。
- 客户端刷新、断网重连或服务重启后不应生成重复消息或重复写操作。
- 品牌图片加载失败时使用文本名称和安全默认样式。

### 11.4 响应式与可访问性

- 客户前台支持常见手机和桌面视口。
- 管理后台优先桌面效率，同时保证平板和手机可完成审批、知识缺口处理等关键任务。
- 交互控件支持键盘操作、可见焦点、语义标签和合理对比度。
- 动态消息和错误状态应适配屏幕阅读器。

### 11.5 隐私与合规

- 客户前台明确展示当前服务提供企业和隐私政策链接。
- 不在日志中记录完整 API Key、访问令牌和其他秘密。
- 会话、反馈和人工升级记录遵循租户保留和删除策略。
- 企业删除数据时同步处理业务数据库、索引、对象存储和缓存。

## 12. 核心验收场景

1. **入口隔离**：下游客户进入 `/support`，只能看到企业品牌、对话、历史、引用和人工服务，不能看到后台导航。
2. **后台鉴权**：终端用户直接访问 `/admin` 或管理 API 时被拒绝。
3. **企业品牌**：A 企业和 B 企业使用各自名称、Logo、欢迎语和建议问题，不发生串租户。
4. **未知资料**：知识库未收录某厂商售后政策时，前台明确提示资料不足，并创建可处理的知识缺口。
5. **知识补充闭环**：企业编辑上传资料，审核发布后，客户再次提问获得正确答案和引用。
6. **引用权限**：用户无法通过修改引用 URL 访问其他租户或无权文档。
7. **Agent 排障**：客服在后台可以查看授权会话的路由和工具失败原因，客户前台看不到这些内部信息。
8. **审批隔离**：审批事项只对有权角色可见，模型和终端用户均不能绕过服务端审批。
9. **人工升级**：客户申请人工服务后，后台出现同一条升级记录，重复提交不会产生重复工单。
10. **故障分类**：智谱不可用时显示服务故障，不创建知识缺口；资料未命中时不显示系统故障。
11. **移动端**：手机客户前台无内容重叠；手机管理端可以完成审批和知识缺口处理。
12. **平台边界**：平台运营人员默认只能看到租户状态和聚合指标，不能读取企业私有知识正文。

## 13. 分阶段交付建议

### 阶段 3A：界面和权限边界（P0）

- 新建 `/support` 客户前台和 `/admin` 管理后台路由树。
- 拆分客户聊天与 Agent 工作台布局。
- 实现角色化后台导航和路由守卫。
- 隐藏并阻断客户对内部 Agent 数据的访问。
- 增加企业品牌配置的基础数据和前台渲染。
- 完成桌面端、移动端和跨角色验收测试。

**退出条件**：客户前台和企业后台可以独立使用；终端用户无法访问后台页面或内部数据；企业品牌按租户正确展示。

### 阶段 3B：企业管理闭环（P1）

- 新增会话与人工服务、成员与角色、审计日志、系统设置页面。
- 完善知识中心的空间、版本、权限和前台预览。
- 增强知识缺口的聚合、分派和回归验证。
- 增加反馈、服务质量和故障分类指标。

**退出条件**：AI 企业能够独立完成成员管理、知识运营、人工升级和服务质量查看。

### 阶段 3C：渠道发布与生产化（P1）

- 支持企业自定义域名或嵌入式客户服务组件。
- 联调正式企业 SSO 和首个真实人工服务/工单连接器。
- 落实 PostgreSQL、对象存储、异步任务和生产审计能力。
- 完成安全、容量、备份恢复和客户数据删除演练。

**退出条件**：满足受控企业试点的部署、隔离、运维和恢复要求。

## 14. 优先级与依赖

| 优先级 | 交付内容 | 主要依赖 |
| --- | --- | --- |
| P0 | 前后台路由分离、客户信息隐藏、后台 RBAC、基础品牌、知识与审批闭环 | 现有身份、租户、会话、知识、审批 API |

## 15. 开发前需要确认的产品决策

1. 客户前台首批采用独立路径、自定义子域名，还是嵌入式组件？
2. 下游客户必须登录，还是允许企业按渠道开启匿名咨询？
3. 首批试点是否需要企业 Logo、主色、欢迎语和建议问题之外的深度白标？
4. 首个人工服务连接器选择企业微信、钉钉、Zendesk、Jira Service Management、ServiceNow 还是其他系统？
5. 管理后台是否允许一个用户属于多个企业并进行企业切换？
6. 平台运营人员在企业授权和审计后，是否允许临时访问企业私有内容进行技术支持？
7. 首批是否实现租户自带智谱 API Key，还是继续由平台统一提供模型额度？
8. 是否将 `/support` 和 `/admin` 作为本地及首批试点的默认路径？

## 16. 建议默认决策

为降低首批开发复杂度，建议采用以下默认值：

- 首批使用同一前端工程中的独立 `/support` 与 `/admin` 路由组，共用后端服务。
- 客户前台优先接入企业已有登录身份；匿名咨询默认关闭。
- 首批白标范围为企业名称、Agent 名称、Logo、主色、欢迎语和建议问题。
- 后台使用预定义角色，不在本阶段实现自定义权限编辑器。
- 平台运营人员默认无企业私有正文和完整会话访问权。
- 继续由平台统一配置智谱模型，BYOK 排入后续阶段。
- 外部互联网搜索继续默认关闭。

## 17. 完成定义

本阶段只有在以下条件全部满足时才视为完成：

- P0 功能和 12 个核心验收场景全部通过。
- 客户前台和企业管理后台具有独立路由、布局、权限和测试覆盖。
- 终端用户获取后台页面、管理 API 或内部 Agent 数据的成功次数为 0。
- 跨租户品牌、会话、知识、引用、反馈和审批泄露测试为 0 次成功。
- 未知问题不使用无关资料兜底，基础设施故障不被记录为知识缺口。
- 自动化测试、前端类型检查、生产构建和关键桌面/移动端浏览器测试通过。
- 产品、研发、安全和首批试点企业代表完成评审并签署验收结论。
